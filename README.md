# 拼好麦 · 两个人都省，才值得拼

**基于麦当劳中国 MCP 的双人拼餐演示作品：选想吃的，核算双方省多少钱，再找附近同店、同时间的搭子。**

[在线体验](https://www.harvey404.com/pinghaomai/) · [演示步骤](docs/DEMO.md) · [作品介绍](docs/PROJECT.md) · [MCP 接入](MCP_INTEGRATION.md) · [验证记录](docs/VALIDATION.md)

![真实三店核价后的双边省钱方案](docs/images/recommendation.jpg)

## 解决什么问题

一个人只想吃汉堡，但套餐里还有薯条和饮料。能否拆给另一个人，且两个人都比各自单点便宜？拼好麦用实时菜单和官方试算回答这个问题，再让同店、同取餐时间的两个人匹配。

本项目为麦当劳程序员创意开发大赛准备的独立作品，非麦当劳官方产品。**只查询、核价与演示匹配，不创建真实订单，不收款、不付款、不购卡。** 仓库公开不代表已完成比赛报名。

## 只做两个入口

### 发起拼单

1. 选城市、地标和范围，查询附近门店；支持浏览器定位，西安有二级地标分类。
2. 选择 1–5 家门店和取餐时间，点一个想吃的选项，也可自己输入。
3. 至多推荐 3 个方案：**每家候选门店的两个人都比各自餐品单点参考价便宜**才展示。任一参考价缺失、同价或更贵则不推荐，不凑满三个。
4. 卡片显示双方食物、承担额、你省多少、搭子至少省多少及剩余餐品吸引力分数。
5. 先按发起人承担额升序，同价再按剩余餐品评分降序。确认食物和金额后发布一份覆盖多家店的邀请。

### 查看待拼单

按地标范围和门店找单，可填想吃什么、预算。搭子选一家店领取；一处领取后，其余门店同时下架。退出也关闭原邀请，不自动重新上架。

## 实测：一份三件套，两个人都省

2026-10-23 查询西安开元、北大街、钟鼓楼三店，预约取餐 2026-10-24 12:00；以下为当次记录，**不是长期价格承诺**：

| 分配 | 拼成后承担 | 相比各自餐品单点参考价节省 |
| --- | ---: | ---: |
| 发起人：麦辣鸡腿汉堡 | ¥16.04 | ¥6.46 |
| 搭子：中薯条＋可乐中杯 | ¥17.46 | ¥6.04–7.04，依门店 |
| 套餐合计 | ¥33.50 | 两方分别核验 |

中杯可乐不能直接用菜单“可乐”的起始价代替。项目通过单点详情精确匹配杯型编码，再调用 `calculate-price` 补齐参考价。[可复核的最小价格记录](docs/evidence/prices.json)

参考价来自平台连接账号、同店同时段的菜单或单品试算，并非各用户优惠券后的最低单买价；不保证真实库存或成交。套餐候选最多核验 8 款，不宣称全菜单最优。剩余餐品分数是公开规则，不是拼成概率。推荐后手动修改分配或金额会重新评分，但不能继续把原推荐的节省金额视为新分配的保证。

## 本地运行

Python **3.10+**，运行和测试仅用标准库，无需安装第三方 Python 包。Node.js 仅用于可选的前端语法检查。

```sh
git clone https://github.com/harvey-404/pinghaomai.git
cd pinghaomai
```

在麦当劳官方 [MCP 平台](https://open.mcd.cn/mcp) 登录，自行获取 Token。**不要把 Token 发到 Issue、提交记录或前端。** 用编辑器将其保存在仓库以外的本地私密文件，不使用含真实值的终端命令。然后仅设置文件路径：

```powershell
# Windows PowerShell；替换成你自己的私密文件路径
$env:MCD_TOKEN_FILE = 'C:\private\mcd-token.txt'
python server.py --port 8766
```

```sh
# macOS / Linux；私密文件应只允许本人读取
export MCD_TOKEN_FILE="$HOME/.config/pinghaomai/token"
python3 server.py --port 8766
```

打开 `http://127.0.0.1:8766/`。也支持服务端 `MCD_TOKEN` 环境变量，勿把值写进源码。未配置凭据时首页仍可打开，真实查询会提示配置；项目不暗中回退到假价格。

### 在一台电脑模拟两个人

发起人用 `http://127.0.0.1:8766/`，搭子用无痕窗口访问同一地址；也可在另一个窗口使用 `http://localhost:8766/`，利用不同站点存储形成独立身份。普通同源新标签页会共享身份。两人需查询相同地标范围和门店。

浏览器身份是随机能力令牌，不是正式账号。保持私密，不用麦当劳 Token 代替。清除站点存储会失去原身份，不能据此恢复已发邀请的管理权限。

## 让 AI 来找搭子

项目自身也提供 MCP：`http://127.0.0.1:8766/mcp`；在线演示端点为 `https://www.harvey404.com/pinghaomai/mcp`。

| 工具 | 能力 |
| --- | --- |
| `find_nearby_pending` | 实时查询门店后找附近待拼邀请，按口味、预算推荐 |
| `get_invitation` | 查看邀请、报价和状态 |
| `claim_invitation` | 用户明确同意后领取，与网页共享唯一占位锁 |

连接需配置持久随机 `X-Actor`（至少 16 个可打印 ASCII 字符）。示例配置只含环境变量占位符，客户端是否自动展开变量请查其文档。官方 MCP 负责餐饮数据，拼好麦 MCP 负责本项目的邀请；两者不是同一个服务。详见 [MCP_INTEGRATION.md](MCP_INTEGRATION.md)。

## 实现与边界

Python HTTP 服务、SQLite 与原生 HTML/CSS/JavaScript。一个邀请一行数据，领取用数据库事务完成 `waiting → checking` 原子占位，网络试算后再条件提交；跨门店并发只能有一个赢家。只锁平台邀请，不锁官方库存。

- 官方工具白名单只有四个查询/试算工具，拒绝真实下单和付款。
- 发布、领取、双方确认时重新核价；变化会要求重新确认。
- 默认本机监听；在线版为公开演示，尚无正式账号、消息通知、担保和实际交接服务。
- 距离是官方地标搜索返回距离，不是步行距离，不保证搜索覆盖所有门店。
- 定位仅由用户点击触发，坐标约化后送 Nominatim 解析，不保存定位历史；也可手动选择地标。
- 令牌、数据库和审计日志均只留服务端；公开仓库不携带这些运行文件。
